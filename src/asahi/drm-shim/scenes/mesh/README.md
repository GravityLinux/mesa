# Vertex buffers, indexed meshes and depth

These are ordinary GLES draws with Mesa-generated vertex and fragment mains.
The vertex shader reads actual vertex buffers, the draw packet reads a real
index buffer, and the depth attachment resolves overlapping faces. Both shader
stages use uniforms. Shader mains are cached across changes in values.

After resetting the target and chainloading the intended m1n1, run:

```sh
./run.sh /absolute/path/to/new-output-directory cube
```

The default cube has eight shared vertices and 12 triangles. It renders 28
frames: 14 angles, each drawn twice with reversed primitive order. The runner
validates every frame's color and depth attachment against an independent CPU
rasterizer and checks that reversing order produces identical attachments.
`frameNN.png` images contain only detiled hardware pixels. `validation.json`
contains the numerical results. The reference snaps projected XY to 1/256
pixel before interpolation, with positive halfway cases rounded upward;
transform/viewport arithmetic uses FP32 and Z remains floating point.

A lossless animation can be assembled from the validated hardware PNGs:

```sh
uv run --with pillow python animate.py /absolute/path/to/new-output-directory
```

This writes `rotation.png` (APNG), verifies that every animation frame retains
the exact source pixels, and omits the duplicate order-check frames.

Other controls, each requiring a reset/chainload before its hardware process:

```sh
./run.sh /absolute/path/to/quad quad
T8132_GLES_INDEX32=1 T8132_GLES_FOUR_BUFFERS=1 ./run.sh /absolute/path/to/quad32 quad
T8132_GLES_DEPTH_STATES=1 ./run.sh /absolute/path/to/depth depth
```

The quad uses separate position/color buffers, strides of 20 and 24 bytes,
nonzero attribute offsets, a nonzero index-buffer offset, and repeated vertex
indices. The four-buffer control adds a scalar vertex weight, moves attributes
to API locations 3, 9 and 13, and retains the VS transform UBO. This checks the
full four-pointer budget and Gallium's compacted vertex-element mapping.

The depth control renders near/far overlapping triangles, reversing their
order in each pair. Its ten frames cover LESS and GREATER with writes,
write-disabled depth testing, disabled depth testing, and separate ALWAYS /
NEVER draws in one batch. The flat depth values and clear are checked for every
pixel, including the pixels outside the triangle.

Validated on T8132 M4 with standalone m1n1 on 2026-09-04:

- Indexed quad: 98,304 covered pixels, exact color and coverage, u16 and u32.
- Depth controls: 73,728 covered pixels, exact colors and depth within float
  rounding, including independent state for two draws in one batch.
- Rotating cube: all 28 color/depth frames pass with zero coverage errors,
  at most one color level of rounding error, and maximum depth error
  1.87e-7. Both attachments are byte-identical within every reversed-order pair.
- Existing glUniform and std140 UBO scenes retain their exact attachment
  hashes, as does the 100-triangle procedural scene. All 188 compiler tests pass.

Current limits: FP32 vertex formats with one to four channels, aligned offsets
and strides; up to 32 buffer table entries per stage (vertex buffers and UBOs
share the VS budget); 32 buffer/depth-state draws per batch. Index buffers use
the fixed USC aperture and support u16/u32 triangle lists. Primitive restart,
indirect draws, instanced attributes, other vertex formats, general graphics
control flow, stencil, and general viewport/raster state are outside this
milestone. Depth32Float and the default depth range are the validated depth
configuration. Nonzero baseVertex is encoded but has not been exercised by
this GLES fixture. The carrier still supplies its fixed background clear.
