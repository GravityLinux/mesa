# Apple9 sampled textures

Mesa-generated vertex/fragment shaders use ordinary Gallium texture and sampler
bindings. Supported sampling is FP32 implicit-LOD 2D, with up to sixteen textures and sixteen
independently selected samplers per fragment shader. Repeated samples, structured branches and
loops, nearest/linear minification and magnification, clamp-to-edge, mipmaps,
and nearest/linear mip filtering are implemented. API texture units are compacted
to the hardware binding independently for each draw.

Uncompressed R8, RG8, RGBA8, RGBX8, BGRA8 and BGRX8 UNORM views use the normal
format/swizzle path. BGRA8 backs GL_RGBA8 render targets in the compatibility
attachment path. Mesa's CPU transfer fallback converts uploads when needed;
resource hazards synchronize render-to-texture followed by sampling. Mipmap
generation currently runs on the CPU through synchronized Gallium maps.

After resetting and chainloading m1n1, run:

```sh
src/asahi/drm-shim/scenes/textures/run.sh /absolute/path/to/new-output
```

Each run produces two 256x256 attachments and checks all pixels against an
independent CPU oracle, including alpha. The default samples 64x64 RGBA patterns
and switches API units 3/1 between frames. Reset and chainload before each new
process. The following environment variables select further tests:

| Variables | Coverage |
| --- | --- |
| `T8132_GLES_TEXTURES_MIXED=1` | Three draws per batch: textured/untextured/textured, binding and tint changes, scissors and out-of-range UVs |
| `T8132_TEXTURE_LINEAR=1` | Bilinear filtering; combines with mixed draws, atlases and mipmaps |
| `T8132_TEXTURE_RTT=1` | Render to a canvas, then sample it into the final target without an intervening `glFinish` |
| `T8132_TEXTURE_BLEND=1` | Sample and alpha-blend over a drawn background; combines with RTT |
| `T8132_TEXTURE_REPEAT=1 T8132_TEXTURE_FRAGMENT_SOURCE=.../fragment-repeat.glsl` | Two distinct sampling coordinates |
| `T8132_TEXTURE_LOOPS=7 T8132_TEXTURE_FRAGMENT_SOURCE=.../fragment-fixed-loops.glsl` | 49 samples in nested constant-bound loops; guards against frontend unrolling/code-size growth |
| `T8132_TEXTURE_LOOPS=9 T8132_TEXTURE_FRAGMENT_SOURCE=.../fragment-loops.glsl` | 81 samples per pixel in nested runtime loops, spatial branches, Boolean uniform changes |
| `T8132_TEXTURE_MIPS=384` | Full NPOT mip pyramid with distinct colors, all implicit LODs, triangle/scissor edges |
| `T8132_TEXTURE_MIPS=994 T8132_TEXTURE_MIP_HEIGHT=950` | Rectangular mip pyramid; catches inherited large-level allocation padding omitted by a per-level area model |
| `T8132_TEXTURE_MIPS=1846 T8132_TEXTURE_MIP_HEIGHT=760 T8132_TEXTURE_MIP_LINEAR=1 T8132_TEXTURE_LINEAR=1` | Wide rectangular atlas with trilinear filtering across all levels |

Use absolute paths for fragment-source overrides. The attachment is read through
the shim's synchronized dump facility; `glReadPixels` is not covered.

The compatibility packager requires the complete external
`render_texture_coords8_launch.bin` (256 bytes, SHA-256
`380fe0f9a88408f1258947bf092e4ab4261217d6953005abb4ddac04af8fbc8e`).
The launcher stays opaque; both API shader mains are generated by Mesa.
Initial capture provenance is in `tmp/apple9-textures/`; the expanded feature
validation and discovered compiler bugs are in `tmp/apple9-texture-features/`.

See `../multitexture/README.md` for simultaneous bindings and per-draw rebinding
validation. Remaining limits include dynamic descriptor indexing, compressed
and integer formats, and non-2D or multisampled textures. This is a
bounded bring-up path, not a claim of complete GLES conformance.

### Integer texel fetch

`fetch.glsl` uses integer coordinates and a uniform LOD, with the ordinary
coordinate-dependent texture oracle. `fetch-mips.glsl` selects all eight levels
of a 128x128 texture from fragment position. `fetch-mips-mixed.glsl` combines two
fetches and two ordinary samples, alternating the checked texture by level.
Reset/chainload before each hardware run, as for the other cases:

```sh
T8132_TEXTURE_FRAGMENT_SOURCE="$PWD/fetch.glsl" ./run.sh /tmp/fetch-coordinates
T8132_TEXTURE_MIPS=128 T8132_TEXTURE_FRAGMENT_SOURCE="$PWD/fetch-mips.glsl" ./run.sh /tmp/fetch-mips
T8132_TEXTURE_MIPS=128 T8132_TEXTURE_FETCH_HOSTILE_SAMPLER=1 T8132_TEXTURE_FRAGMENT_SOURCE="$PWD/fetch-mips.glsl" ./run.sh /tmp/fetch-sampler-independence
T8132_TEXTURE_MIPS=128 T8132_TEXTURE_FETCH_MIXED=1 T8132_TEXTURE_FRAGMENT_SOURCE="$PWD/fetch-mips-mixed.glsl" ./run.sh /tmp/fetch-mixed
```

The hostile sampler case binds linear-filtering sampler objects clamped to LOD4;
fetches must still select every requested level. The driver allocates one internal
nearest/mipmap sampler after the live API samplers because Apple9 fetch packets
consume sampler LOD state. This currently shares the sixteen encoded sampler
slots, leaving fifteen API samplers for shaders that also fetch. Fetch-only shaders
have no API sampler dependency.

### Discard and projective sampling

Use `T8132_TEXTURE_FRAGMENT_SOURCE` with `discard.glsl` or `discard-plain.glsl`
and `T8132_TEXTURE_DISCARD=half`. Both preserve the background on the left half;
the latter exercises buffer-only bindings. `discard-loop.glsl` uses nested
branches inside a uniform-count loop: set `T8132_TEXTURE_DISCARD=loop` and
`T8132_TEXTURE_LOOPS=3`. The oracle checks the two different horizontal cutoffs.
Combine `discard.glsl` with `T8132_TEXTURE_DEPTH=always` to check that discarded
pixels preserve background depth, or `T8132_TEXTURE_BLEND_MODE=dstalpha` to check
blending against a non-opaque destination. Depth attachments are checked separately
from color. `projective.glsl` checks a varying projective denominator against the
ordinary texture oracle.

Discard needs the external opaque `render_coverage_texture_launch.bin` (256 bytes,
SHA-256 `3964d362c7ae26c3011ca81d9cd82119e265fb808521e42a5fe7d4c892d406a8`).
It retains the texture/sampler + four-buffer argument layout, with the authored
main relocation at +0x62. Provenance: `tmp/apple9-general-graphics/coverage-bindings.metal`,
`coverage-bindings-capture/`, and `extract-coverage-launch.py`. No helper code was
decoded or reconstructed. A separate native-envelope test executes the exact
Mesa-generated screen-position/discard main and checks all4096 pixels.
The production path remains single-sample; fragment sample-mask outputs and
helper-invocation queries are not implemented by this change.

`T8132_TEXTURE_RTT=1 T8132_TEXTURE_COPY=1` additionally copies the rendered
canvas with `glCopyTexSubImage2D`, samples that copy, and checks every pixel from
`glReadPixels` against the authored texture pattern for both frames. Run this
through `run_t8132_gles_triangle.sh` with the texture scene sources and
`T8132_GLES_TEXTURES=1`, without `G16G_RENDER_ATTACHMENT_DUMP` or `ASAHI_SHIM_PULL`,
to exercise on-demand CPU readback rather than automatic submission readback.


### LOD, gradients, views, anisotropy, and formats

`lod.glsl` tests fractional explicit LOD; `bias.glsl` tests shader bias with
implicit derivatives; `gradient.glsl` and `gradient-mixed.glsl` test explicit
FP32 derivatives and mixed publication reuse. Use `T8132_TEXTURE_MIPS=128` and
`T8132_TEXTURE_MIP_LINEAR=1`. The gradient cases also support non-square
textures via `T8132_TEXTURE_MIP_HEIGHT=64`. `T8132_TEXTURE_BIAS` supplies shader
bias for `bias.glsl`, including negative and saturating values.

`T8132_TEXTURE_BASE=2 T8132_TEXTURE_LAST=4` with `lod.glsl` verifies view-relative
LOD and clamping. Native views keep the original allocation address and
size; the first/last levels occupy separate descriptor fields.

`T8132_TEXTURE_ANISO=16` with `anisotropy.glsl`, the 128-square mip chain,
linear filtering, and linear mip interpolation checks unequal derivative axes.
Native sampler anisotropy is log2 of 1/2/4/8/16 at bits20..22.

`T8132_DESKTOP_GL=1 T8132_TEXTURE_SAMPLER_BIAS=1.25` binds opposite sampler
biases on the two textures. This works with `lod.glsl`, `bias.glsl`, and
`gradient.glsl`; the expected mip changes sign between frames. Sampler biases
use an ordinary per-draw system-value buffer keyed by original API sampler
binding. Integer fetch remains independent of this state.

`T8132_TEXTURE_FORMAT` selects `srgb`, `rgb565`, or `rgba16f`. With
`T8132_TEXTURE_LINEAR=1`, the first two use the ordinary fragment shader;
half-float uses `float.glsl`, which maps negative and greater-than-one samples
into visible colors. The sRGB oracle decodes before filtering and keeps alpha
linear. These are sampling formats; the compatibility color attachment path
still supports only BGRA8 UNORM/X8.

`T8132_TEXTURE_GENERATE_MIPS=1 T8132_TEXTURE_MIPS=128` with
`generated-mips.glsl` checks generated mip chains for all three formats. The
CPU fallback uses shared Mesa float unpack/pack routines around its bilinear
average, including sRGB conversion. Packed-format test values avoid halfway
rounding ties, so each mip has a unique exact reference.

The development runner explicitly requests a GLES3 subset (or GL3.3 for the
sampler-bias test). These version overrides do not assert driver conformance.
Unsupported attachment formats and sampling resource types are rejected by
format/capability queries instead of silently using incompatible Apple8 paths.

### Stencil

`T8132_TEXTURE_STENCIL=ops` checks all eight stencil operations, independent
front/back state, full/masked writes, and saturation/wrap endpoints. `sfail`
and `zfail` select the stencil-fail and depth-fail update paths. `compare`
checks all eight comparison functions with masked references. `persist` forces
a submission boundary before verification. `discard`, `discard-repeat`, and
`discard-color` check both zero-color and color-writing fragment programs,
repeated demotion, killed samples retaining stencil, and surviving samples
updating stencil exactly once. Every case checks the S8 attachment separately
from color; `zfail` also checks preserved depth.

Early coverage demotion must not mark surviving samples as affected: otherwise
the stencil operation occurs at both demotion and final publication. Depth
writes alone hide that bug because writing the same depth twice is idempotent.
